## 1. 원칙

주관사 자료의 원칙을 그대로 따른다.

- 4일차(10/2)까지 End-to-End를 한 번 성공시킨다. 안 되면 새 기능 추가를 멈추고 핵심 흐름에 집중한다.
- 기능을 늘리기보다 한 흐름을 끝까지 동작시킨다.
- 디자인에 시간을 쓰지 않는다.
- 출처와 AI 활용은 그날그날 기록한다.
- 하루 작업이 끝나면 커밋하고 [진행기록](05_진행기록.md)을 갱신한다.

### 일차별 세부

**2일차 (9/30)**
1. Python 3.11 이상 설치, 가상환경, 패키지 설치, `requirements.txt`
2. `.env`로 API Key 관리, `.env.example` 작성
3. 가상 자료 5개 작성 (개인정보 없는 구버전·최신본 양식, 절차 메모)
4. 상태 정의와 흐름 골격. 도구는 빈 껍데기로 연결
5. 목표 해석과 계획 수립 노드에 LLM 연결
6. 실행 로그 저장과 화면 표시

**3일차 (10/1)**
1. 문서 읽기: PDF, Word, Excel, HWPX
2. 버전 묶기와 최신본 판별. 판별 근거를 함께 출력
3. 변경점 비교와 유형 분류
4. 절차 복원. 단계마다 근거 문장을 붙임
5. 근거 문장 실존 확인. 실패하면 재추출

**4일차 (10/2)**
1. 충돌·누락 탐지
2. 책임자 확인 요청. 실행을 멈췄다가 답변 후 재개
3. 체크리스트와 업무 초안 생성, 필수값 검사
4. 신규자 단계 완료 입력, 미완료 알림, 책임자 승인, 완료 판정
5. 처음부터 끝까지 한 번 실행하고 로그와 화면을 저장

**5일차 (10/3)**
1. 오류 상황 6개 처리
2. 응답 기록과 재생 모드
3. 개인정보 가림, 폴더 허용 목록, 문서 속 지시 무시
4. 책임자 답변 저장과 재사용
5. 실제 자료를 받았으면 교체 투입

**6일차 (10/4)**
1. 테스트 케이스 7건 실행과 기록
2. 블라인드 평가 세트 채점
3. 사용자 검증 3명과 확인서
4. 기존 방식과 시간·누락 비교
5. 실패 유형 분류

**7일차 (10/5)**
1. 시연 동선 확정 후 영상 촬영 (편집 최소화)
2. 보고서, 기술설명서, 발표자료
3. 출처·AI 활용 신고서
4. 제출용 저장소 분리, 실행 안내 작성, 비밀키 검사

## 6. 커밋 규칙

- 작업 단위가 끝날 때마다 커밋하고 바로 올린다.
- 커밋 메시지는 무엇을 왜 했는지 한글로 쓴다.
- AI 도구가 작성에 참여한 커밋은 메시지 끝에 표시한다.
- API Key, 실제 자료, 서명된 서류는 올리지 않는다.
- 하루 끝에 [진행기록](05_진행기록.md)과 [출처 기록](04_출처_AI활용_기록.md)을 갱신한다.
