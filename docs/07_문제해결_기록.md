# 문제 해결 기록

개발 중 막혔던 것과 어떻게 보완했는지를 적는다. 날짜순, 발견한 그날 적는다.
보고서의 "테스트·한계" 절과 본선 질문 "실패하면 어떻게 대응하나"의 근거가 된다.
사소한 오타 수정은 적지 않는다. 설계나 동작이 바뀐 것만 적는다.

## 보는 법

| 열 | 뜻 |
|---|---|
| 증상 | 무엇이 안 됐나 (사용자 눈에 보인 것) |
| 원인 | 왜 그랬나 |
| 보완 | 무엇을 바꿨나 |
| 확인 | 고쳐졌다는 증거 (테스트, 실행 ID, 커밋) |
