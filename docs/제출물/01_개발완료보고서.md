## 2. 프로젝트 개요

**문제.** 소규모 사업장은 한 사람이 한 업무를 전담한다. 담당자가 빠지면 후임자는 매뉴얼 없이 남겨진 파일을 뒤지다 구버전 양식을 쓰고 필수 단계를 빠뜨린다. 중소기업이 전체 근로자의 83%를 고용하고(중소벤처기업부), 일자리 이동자 비율은 중소기업 17.8%로 대기업 13.2%보다 높다(통계청 2021). 인계 매뉴얼을 쓸 사람도 시간도 없는 곳에서 가장 자주 일어나는 문제이며, 업무혁신 분야의 예시 업무(견적·문서·인사·경영지원) 그 자체다.

**사용자.** 전담 인사·교육 인력이 없는 10인 안팎 사업장의 **신규자**(복원된 절차·체크리스트로 첫 업무 수행)와 **책임자**(질문 답변·절차 수정·완료 승인). 범위는 업무 1개와 그 자료 폴더(PDF·Word·Excel·HWP·HWPX·텍스트).

**목표와 성공지표.** "섞인 폴더 하나로 신규자가 첫 업무를 끝내고 책임자가 승인하는 것."

| 성공지표 | 측정 방법 | 결과 |
|---|---|---|
| 첫 업무 파악 시간 | Before(파일만) / After(일잇다) 교차 비교, 검증자 2명 | 평균 7분 58초 → 1분 52초, 누락 2 → 0, 틀린 양식 0 → 0 |
| 근거 표시율 | 복원 단계 중 원문 인용이 실존하는 비율 | 가상 9/9·6/6·7/7·10/10, 실제 10/10·16/16·5/5 |
| 변경점 탐지율 | 시드 평가 20쌍 (개발자 작성, 비블라인드) | 20/20, 오탐 0 |
| 누락 단계 수 | 실제 담당자가 복원 절차를 검토 | 자료에 있는 7단계 모두 일치, 자료에 없는 2단계는 책임자가 추가 |

## 3. 개발 세부 내용

**3.1 시스템 구조와 Workflow.** 단순 질의응답이 아니다. LLM 호출 5종이 상태로 이어지고(목표 → 계획 → 자료 → 최신본 → 절차 → 질문·답변 → 체크리스트 → 승인), 사람이 답해야 하는 4곳에서 멈춘 뒤 같은 자리에서 잇는다. 번호 ①~⑦은 기술설명서·시연영상·발표자료와 같다.

| 단계 | 하는 일 | 6요소 |
|---|---|---|
| ① 입력 | 목표 한 문장 + 파일 업로드. 허용 폴더만 읽고 파일을 옮기거나 지우지 않는다 | Goal |
| ② 목표 해석·계획 | 업무·신규자·책임자·완료 조건을 구조화(LLM). 업무·신규자가 없으면 되묻고(최대 2회), 자료 목록을 보고 단계별 도구를 계획한다 | Goal · Planning |
| ③ 자료 읽기·버전 정리 | 6형식을 읽고 사본을 묶는다. 최신본은 개정번호 → 내용 속 날짜 → 수정 표시 → 추가분 순으로 판별하고, 같으면 책임자에게 묻는다. 변경점은 항목 단위 비교(코드) + 업무 영향 분류(LLM) | Tool Use · Reasoning |
| ④ 절차 복원·근거 검증 | 개인정보 형식을 가린 최신 자료로 단계와 근거를 복원(LLM). 인용이 원문에 실존하는지 코드로 확인(일치율 0.85), 미확인은 최대 2회 재추출 뒤 질문으로 돌린다 | Tool Use · Feedback |
| ⑤ 책임자 확인 | 실행을 멈추고 묻는다. 저장을 선택한 이전 답변(유사도 0.6 이상)은 답변 칸에 제안만 하고 책임자가 확인해야 반영된다. 절차 수정·삭제·추가, 미답은 '미확정' | Memory/State |
| ⑥ 체크리스트·신규자 수행 | 체크리스트를 만들고(미확정은 선택 항목) 수행 표시·메모를 저장한다 | Feedback |
| ⑦ 승인·완료 판정 | 필수 미완료면 승인을 잠근다. 보류하면 사유와 함께 돌려보내고 보완 뒤 재승인. 완료 시 지표를 기록하고 인수인계서(Word)를 만든다 | Feedback |

실제로 갈리는 판단 분기는 5개다. 목표가 불완전하면 되묻기 · 최신본 근거가 부족하면 묻기 · 근거 인용이 원문에 없으면 재추출 뒤 묻기 · 미답은 '미확정'으로 신규자에게 단정하지 않기 · 필수 미완료면 승인 보류 → 보완 → 재승인. (증거 실행: 되물음 `20261003-011519-2c768e`, 끊김 뒤 재진입 `20261003-161943-f219ec`)

**3.2 활용 데이터.** 가상 자료 3종(거래처등록_견적 10개 — 구버전·최신본 양식, 사본, 어긋나는 메모, 손상 hwp / 출장비_정산 6개 / 비품_구매 6개, 정답 메모 동봉, 저장소 포함, 스크립트로 재생성). 실제 사업장 자료 3건(A/S 업무 파일, 도장 공정 인수인계표, 배관 보온 견적서 — 제공자 동의, 가명 사본만 LLM에 전달, 저장소 미포함·대회 후 삭제). 실행마다 `runs/<실행 ID>/log.jsonl`에 판단·도구·토큰·재생 여부가 남는다.

**3.3 AI·Tool·알고리즘.** Python 3.12 · LangGraph 1.2(상태 그래프, interrupt, SQLite 체크포인트) · Claude Opus 5.5(Anthropic API, JSON 스키마 강제 출력, 응답 기록·재생) · Streamlit 1.64 · SQLite. LLM 호출 5종(목표 해석·계획·변경 영향 분류·절차 복원·체크리스트)은 비정형 이해만 맡고, 코드 도구 6종(scan_folder · parse_document · group_versions · pick_latest · diff_versions · verify_evidence)이 결정적 처리를 맡는다. 사람은 충돌 해소와 승인을 맡는다. 외부 연동은 파일 6형식(HWP 직접 구현)·SQLite·Anthropic API뿐이다.

**3.4 단계별 개발.** 9/29~30 설계·테스트 계획, 파일 읽기 6형식, 버전 판별·변경 비교, 가상 자료 1종 → 10/1~2 LangGraph 그래프 9노드·사람 확인 4곳, 절차 복원·근거 검증, 책임자 확인 화면, End-to-End 첫 완주 → 10/3 실제 자료 2건 완주, 공개 테스트 링크(실행 격리·재개 코드·하루 한도), 실사용자 1 → 10/4 가상 자료 2종 추가, 실사용자 2, 보류→보완→재승인, 인수인계서(Word) → 10/5~6 실사용자 3, Before/After 교차 측정, 답변 제안(선택 저장), 업로드 화면·문서 간소화, 시연영상.

**4.5 차별성.** 범용 AI에 파일을 올리면 어느 파일이 최신인지 가리지 않고, 근거를 지어낼 수 있으며, 인계가 끝났는지 모른다. 사내 위키·RAG는 누군가 써 두어야 하고 물어본 것만 답한다. 인수인계서 양식은 담당자가 떠나면 쓸 사람이 없다. 일잇다는 **내용으로 최신본을 판별하고, 인용 실존을 코드로 확인하고, 승인까지 추적해 인수인계서를 결과로 낸다.** 독창성은 "검색"이 아니라 **"인계 완료 판정"** 을 목표로 둔 점이다. 자료에 없는 단계는 만들지 않고 책임자가 추가하게 하므로 지어낸 절차가 신규자에게 가지 않는다. 최신본 판별과 근거 검증을 일부러 코드로 둔 이유도 같다. AI가 지어낸 근거를 잡아내려면 판정자가 AI가 아니어야 한다.

## 5. 기대효과

**5.1 성과·효과.** Before/After: 조건이 비슷한 검증자 2명(동일 전공, 경력 4–5년, 해당 업무 경험 없음)이 가상 자료 2종을 교차로 수행해 첫 업무 파악 시간 평균 7분 58초 → 1분 52초(7:20→1:20, 8:36→2:24), 누락 2 → 0, 틀린 양식 0 → 0. 사용자 검증 3명 — 쓰겠다 5/5·4/5·4/5, 맞음 4/5·4/5, 쉬움 2/5·2/5 → 진행 단계와 할 일을 상단에, 처리 중 진행 막대와 AI 판단 내역, 버튼 위치 통일로 반영. 비용은 1회 완주 약 0.2달러. 적용 범위는 가상 업무 3종 + 실제 업무 3종, 자료 6형식.

**기대효과와 적용가능성.** 인계 매뉴얼 없이 첫 업무 완료, 책임자 확인을 거친 인수인계서가 자동으로 쌓임, 구버전 양식·필수 단계 누락 사고 감소. 설치형이라 자료가 PC 밖으로 나가지 않고 API 호출만 외부로 간다. 파일을 끌어 넣고 목표 한 문장이면 시작한다. 책임자 질문 수(4~17건)가 곧 "자료에 빠진 암묵지"의 양이라 떠나기 전 무엇을 적어 둬야 하는지도 알려 준다. 업무 종류는 자료만 바꾸면 늘어난다.

**5.4 한계와 발전 계획.** 계획은 LLM이 세우지만 실행 순서는 고정 그래프라 재계획이 없다 · 근거 확인은 글자 일치라 의미 왜곡은 못 잡고, 자료에 없는 단계는 책임자가 추가한다 · 자동 가림은 형식만 잡으며 사진·스캔, 구형·손상 파일은 읽지 못한다 · 로그인·권한이 없어 두 역할 화면이 한 사이트에 있다 · 시드 평가는 비블라인드, 범용 AI와의 직접 비교는 하지 않았다 · 가격·시장 규모 미조사, 검증 표본 소수. 발전 계획: 역할별 로그인·알림 → 스캔 OCR → 재계획 → 블라인드 평가·범용 AI 비교 → 업무 초안·이해 확인 문답.
