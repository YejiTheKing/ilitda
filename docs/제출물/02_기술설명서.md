# <별지 1> AI Agent 기술설명서 (1페이지)

| 항목 | 기재 내용 |
|---|---|
| 팀명 / 부문 / 주제 | 바톤터치 (1인, 안예지) / 일반부 / 업무혁신 (20) |
| 작품명 | 일잇다 — 담당자가 떠난 자리의 업무를 복원해 신규자의 첫 업무 완료까지 이끄는 인수인계 AI Agent |
| 해결 문제 | 소규모 사업장은 한 사람이 한 업무를 전담한다. 담당자가 빠지면 후임자는 매뉴얼 없이 남은 파일을 뒤지다 구버전 양식을 쓰고 필수 단계를 빠뜨린다. 인계 매뉴얼을 만들 인력도, 시간도 없다. |
| 대상사용자 | 신규자(후임자) 1명 + 책임자(대표·관리자) 1명. 전담 인사·교육 인력이 없는 10인 안팎 사업장 |
| Agent Goal | 자료 폴더 하나로 ① 최신본·변경점 판별 ② 근거가 원문에 실존하는 절차만 복원 ③ 충돌·빈틈은 단정 없이 책임자에게 질문 ④ 신규자가 첫 업무를 끝내고 책임자가 승인하면 인계 완료 판정 |
| 사용 AI/LLM/모델 | Claude Opus 5.5 (Anthropic API). 호출 5종 — 목표 해석, 계획, 변경 영향 분류, 절차 복원(근거 인용), 체크리스트. JSON 스키마 강제 출력, 응답 기록·재생(로그에 replay 표시).<br>LangGraph 1.2 · Streamlit 1.64 · Python 3.12 |
| 사용 Tool/API/Data/장비 | 외부 연동 3종: ① 파일 6형식(PDF·Word·Excel·HWP·HWPX·텍스트, 허용 폴더만 읽기) ② SQLite 2개(체크포인트·답변 기억) ③ Anthropic API<br>내부 도구 6종(코드): scan_folder · parse_document · group_versions · pick_latest · diff_versions · verify_evidence<br>Data: 가상 자료 3종(파일 22개, 정답 메모 포함, 저장소 포함) · 실제 사업장 자료 3건(가명 사본만, 저장소 미포함) · 실행 기록 runs/<ID>/log.jsonl |
| Memory/State/Feedback 구현 | State: 목표·계획·자료·최신본·변경점·절차·질문/답변·체크리스트·승인·지표를 SQLite 체크포인트에 보존. 사람 확인 4곳에서 멈추고 같은 자리에서 재개<br>Memory: 책임자가 저장을 선택한 답변만 기억해 같은 업무 재인계 때 유사도 0.6 이상이면 답변 칸에 미리 채워 제안, 책임자 확인 뒤 반영(자동 반영 없음)<br>Feedback: 근거 인용을 코드로 원문 대조(일치율 0.85), 미확인은 재추출 뒤 질문 · 책임자 수정·추가 반영 · 필수 미완료면 승인 보류 → 보완 → 재승인 · LLM 실패 시 상태 보존·재시도 |
| 핵심 Workflow (End-to-End 동작시나리오) | ① 입력: 목표 한 문장 + 자료 폴더 [Goal]<br>② 목표 해석·계획: 업무·신규자·책임자·완료 조건 구조화, 빠지면 되물음(최대 2회), 자료 목록으로 도구 계획 [Goal·Planning]<br>③ 자료 읽기·버전 정리: 사본 묶기, 최신본 판별(개정번호→날짜→수정 표시→추가분), 항목 단위 변경 비교·영향 분류 [Tool·Reasoning]<br>④ 절차 복원·근거 검증: 개인정보 가림 → 단계·근거 복원 → 원문 실존 확인 → 미확인 재추출 [Tool·Feedback]<br>⑤ 책임자 확인(멈춤): 질문(이전 답변은 제안으로 미리 채움), 절차 수정·추가, 미답은 미확정 [Memory]<br>⑥ 체크리스트·신규자 수행(멈춤) [Feedback]<br>⑦ 승인·완료 판정(멈춤): 필수 미완료면 보류 → 보완 → 재승인 [Feedback]<br>시연영상(실행 20261006-045149-4c4a0e) 자막 번호와 같다. 호출마다 실제 호출인지 저장 응답 재생인지를 화면과 로그에 표시한다 |
| 핵심기능 3~5개 | 1) 최신본 판별·변경점 탐지 2) 절차 복원 + 근거 실존 확인 3) 충돌·빈틈 책임자 확인과 '미확정' 처리 4) 인계 진행: 체크리스트 → 승인(보류·보완·재승인) → 완료 판정 (업무 초안·이해 확인 문답은 미구현) 5) 결과물: 승인된 절차와 '확인할 것'을 인수인계서(Word)로 출력, 저장을 선택한 책임자 답변은 다음 인계에 제안(기억) |
| 기존자산/ 8일 신규개발분 | 기존자산: 코드 반입 없음. 설명회 전 실험 코드 1개와 본인이 병행한 실험 버전에서 방식 3가지(개정번호 우선, 항목 단위 비교, 책임자 단계 수정)만 참고해 10/3 새로 구현<br>8일 신규개발: 저장소 전체 (커밋 129, 코드 5,595줄, 첫 코드 커밋 9/30). Claude Code 사용, 출처·AI 활용 신고서에 기재 |
| 대표 테스트 5건 결과 | ① 정상 완주: 9단계 근거 9/9, 질문 6건, 체크리스트 12/12 ② 자료 충돌: 출처 2개 이상을 인용해 질문, 답변 반영 ③ API 오류: 상태 보존 → 재시도 → 같은 자리 재개 ④ 악의적 입력: 삭제 지시 미실행, 개인정보 3건 가림 ⑤ 결과물: 승인 뒤 인수인계서(Word) 생성, 절차 9단계·확인할 것 포함<br>대표 8건 8/8(두 차례) · pytest 24 · 화면 자동 테스트(시작 화면 2모드·저장 실행 4화면·전체 흐름·오류 재개) · 정리 40건. 실제 자료 3건 완주, 실사용자 3명(10/3·10/4·10/5, 의향 5/5·4/5·4/5) (담당자 검토: 7단계 모두 일치, 자료 밖 2단계는 책임자 추가) |
| 현재 완성도 Level | Level 3 (MVP). 핵심기능 4개 완전·1개 부분, 가상·실제 자료 End-to-End 완주, 인수인계서 출력. Level 4 근거 일부: 실사용자 3명(본인 파일 2명)이 승인까지 수행, Before/After 교차 2명: 파악 시간 평균 7:58→1:52, 누락 2→0 |
| 소스코드/저장소(경로) | GitHub https://github.com/YejiTheKing/ilitda (공개) + 동일 내용 ZIP 제출. 실행: `pip install -r requirements.txt && pip install -e .` → `.env.example`을 `.env`로 복사해 ANTHROPIC_API_KEY 기입 → `python scripts/make_sample.py` → `streamlit run src/ilitda/ui/app.py`. 검증: `pytest`(24), `scripts/run_testcases.py`. 키 없이도 저장 응답 재생으로 가상 자료 시연 가능(runs/_llm_cache 포함). 비밀키·실제 자료·실명 제외 확인(scripts/export_submission.sh) |
